# 部署、成本与合规

> 这份文档回答三个「越早想越省钱」的问题：
> 1. 部署架构怎么选，哪些东西必须从第一天就分开？
> 2. AI 调用大概要花多少钱，怎么防止被刷？
> 3. 出生信息属于个人信息，上线前必须处理哪些事？
> 4. 如果以后要商用，现在的依赖许可证有没有坑？

---

## 1. 部署架构

### 1.1 应用本身的形态

一个 Next.js 应用，两类路由：

| 类型 | 路由 | 依赖 | 是否可静态化 |
| --- | --- | --- | --- |
| 纯静态 | `/`、`/bazi`、`/yijing`、`/history`、`/settings` | 无 | 可，但首页含「今日黄历」需按天刷新 |
| 服务端渲染 | `/bazi/result`、`/bazi/reading`、`/almanac`、`/canon` | Node 运行时（历法库） | 否（依赖 URL 参数与当前日期） |
| 服务端 API | `/api/interpret` | 模型密钥、外网出口 | 否 |

**关键点**：`/api/interpret` 是唯一持有密钥、唯一产生外部费用的路由。它必须能独立限流、独立监控、独立熔断。

### 1.2 三种部署方案

| 方案 | 适合 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A. Vercel / Netlify 等托管平台** | 快速上线、个人项目 | 零运维、自动 HTTPS、边缘缓存、环境变量管理 | 按量计费；`/api/interpret` 的执行时长受套餐限制；国内访问速度一般 |
| **B. 单台云服务器（Docker + Nginx）** | 面向国内用户、需要备案与可控成本 | 成本固定、可备案、可放国内 CDN、延迟低 | 需要自己管证书、日志、备份、进程守护 |
| **C. 静态导出 + 独立函数服务** | 只要排盘不要 AI | 可放对象存储 + CDN，成本极低 | 需要把排盘逻辑改成纯客户端（可行，历法库是纯 TS），AI 需另起服务 |

**推荐路径**：先用 A 验证产品，用户量起来或需要备案时迁到 B。迁移成本低，因为没有数据库、没有服务端会话，唯一要搬的是环境变量与域名。

### 1.3 Docker 部署（方案 B 参考）

```dockerfile
# 多阶段构建，产物约 200MB（含 Node 运行时）
FROM node:22-alpine AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci

FROM node:22-alpine AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
# 构建期不需要 AI 密钥：所有 AI 相关代码只在运行时读取环境变量
RUN npm run build

FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/.next ./.next
COPY --from=builder /app/public ./public
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package.json ./package.json
EXPOSE 3000
CMD ["npm", "start"]
```

配套 Nginx 反向代理（HTTPS、gzip、静态资源缓存），`/api/interpret` 单独加 `limit_req`：

```nginx
limit_req_zone $binary_remote_addr zone=ai:10m rate=10r/m;

location /api/interpret {
    limit_req zone=ai burst=5 nodelay;
    proxy_pass http://127.0.0.1:3000;
    proxy_read_timeout 60s;
}
```

> 应用内的内存限流（`checkRateLimit`）在单实例下有效，多实例部署时必须换成 Redis/Upstash，否则每个实例各算各的。

### 1.4 环境变量

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `AI_API_KEY` | 否 | 不配则 AI 功能降级，其余功能完整 |
| `AI_PROVIDER` | 否 | `openai`（默认，兼容任何 OpenAI Chat Completions 网关）或 `anthropic` |
| `AI_BASE_URL` | 否 | 默认官方地址；国内模型服务填其兼容端点 |
| `AI_MODEL` | 否 | 默认 `gpt-4o-mini` / `claude-sonnet-4-20250514` |

模板见 `.env.example`。**`.env*` 已在 `.gitignore` 中，构建产物里不含任何密钥**（密钥只在服务端运行时读取）。

## 2. 个人信息处理

### 2.1 数据分类

| 数据 | 敏感性 | 存放位置 | 生命周期 |
| --- | --- | --- | --- |
| 出生日期 / 时间 | 个人身份可识别信息（结合出生地可唯一指向个人） | 浏览器 localStorage + URL 参数 | 用户删除即消失 |
| 出生地 / 经度 | 同上 | 同上 | 同上 |
| 性别 | 同上 | 同上 | 同上 |
| 排盘结果 | 由上述数据派生 | 同上 | 同上 |
| AI 解读文本 | 派生 + 模型生成 | 仅内存，不落库 | 关闭页面即消失 |
| IP 地址 | 日志类 | 仅在限流 Map 内存中（进程重启即清） | ≤ 60 秒 |

**没有**：姓名、手机号、邮箱、身份证、设备指纹、Cookie、埋点 ID。

### 2.2 数据流（上线前必须核对）

```
浏览器 ──(1) 排盘──▶ 服务端（内存计算，不落盘）
   │                     │
   │                     └─(2) 仅当用户点「AI 解读」
   │                            ├─▶ 模型服务商（跨境传输！）
   │                            └─▶ 返回文本（不落库）
   └── localStorage（唯一持久化位置）
```

第 (2) 步是唯一的对外传输。上线前必须做到：

1. **明示告知**：在点击按钮旁写清楚「哪些字段会发送到服务端与模型服务商」。（当前 UI 已写明发送排盘结构，未发送姓名——因为不收集。）
2. **选择服务商**：若面向中国大陆用户，优先选境内节点/境内模型服务，避免个人信息出境带来的合规义务（《个人信息保护法》第 38–39 条关于跨境提供的要求）。
3. **不落日志**：确认平台/反代的访问日志不记录请求体（默认只记录 URL 与状态码，`/api/interpret` 的请求体含出生信息，务必不要打开 body logging）。
4. **隐私政策**：页面内的说明不构成法律文件。正式上线前需要一份写明收集范围、目的、存储期限、第三方共享、用户权利的隐私政策。
5. **未成年人**：若开放给未成年用户，需要额外的监护人同意机制，或明确限制使用年龄。

### 2.3 分享链接的风险

命盘页的状态全在 URL 里（`/bazi/result?y=1990&m=5&d=15...`）。这意味着：

- 分享链接 = 分享出生信息。UI 已提示，但这是产品设计层面的固有取舍。
- URL 会进入浏览器历史、可能进入聊天记录、可能被平台抓取（`robots: noindex` 已加在命盘与解读页，降低被索引的风险）。

若要彻底解决，需要引入「短链 + 服务端存储」，但那会把「本地优先」变成「服务端存出生信息」，是更大的合规负担。**当前选择是：保留 URL 方案，明确提示，不加索引。**

## 3. 许可证与商用

### 3.1 结论

| 组件 | 许可证 | 商用 | 义务 |
| --- | --- | --- | --- |
| lunar-typescript | MIT | ✅ | 保留版权声明与许可声明 |
| true-solar-time | MIT | ✅ | 同上 |
| Next.js / React / Tailwind / Zod | MIT | ✅ | 同上 |
| TypeScript | Apache-2.0 | ✅ | 保留 NOTICE（若有） |
| `@img/sharp-*`（Next 可选依赖） | Apache-2.0 AND **LGPL-3.0-or-later** | ⚠️ 有条件 | 见 §3.3 |
| caniuse-lite（构建期） | CC-BY-4.0 | ✅ | 署名（不进入产物） |
| 《周易》卦爻辞 | 公有领域 | ✅ | 无 |

**没有 GPL / AGPL / SSPL 代码进入运行时。** 调研阶段已明确排除 AGPL-3.0 的 `tianma-if/zhaoming` 与无许可证的 `shtengteng/tt-qimen`。

### 3.2 MIT 的实际义务

MIT 只要求「在副本或实质性部分中保留版权声明与许可声明」。落地方式：

- 仓库根目录保留 `THIRD_PARTY_LICENSES.md`，列出每个依赖的版权行与许可证全文链接。
- 若做闭源 SaaS，页面上有「开源致谢」入口（`/settings#credits`）即可满足「向用户提供声明」的合理实践。
- 若分发可执行产物（如 Docker 镜像给客户私有化部署），把 `THIRD_PARTY_LICENSES.md` 一并放进产物。

### 3.3 `sharp` 的 LGPL 注意事项

Next.js 将 `sharp` 作为图片优化的可选依赖引入。本项目**没有使用 `next/image`**，因此运行时不会加载它；但它会出现在 `node_modules` 与部分构建产物中。

- **SaaS 场景**（用户通过网络访问，不获得软件副本）：LGPL 的义务基本不触发。
- **分发场景**（交付 Docker 镜像 / 安装包）：LGPL-3.0 要求允许用户替换该库、并提供其源码获取方式。做法：在交付文档中附上 sharp 的上游仓库地址与版本，并说明其为独立动态依赖。
- **想彻底规避**：`npm uninstall sharp` 或在 CI 中裁剪该可选依赖（确认不使用图片优化功能即可）。

## 4. AI 成本模型

> 价格随时变动，下表是**量级估算**，上线前请以服务商当前价目为准。假设一次解读输入约 1,200 tokens、输出约 1,200 tokens。

| 场景 | 单次成本（量级） | 日 1,000 次 | 月成本（量级） |
| --- | --- | --- | --- |
| 小模型（如 gpt-4o-mini 级别） | ¥0.003 – 0.01 | ¥3 – 10 | ¥100 – 300 |
| 中模型（如 gpt-4o / claude-sonnet 级别） | ¥0.05 – 0.15 | ¥50 – 150 | ¥1,500 – 4,500 |
| 国内模型（如通义/豆包/DeepSeek 级别） | ¥0.002 – 0.02 | ¥2 – 20 | ¥60 – 600 |

**结论：AI 不是主要成本，被刷才是。** 一个没有限流的公开接口，一晚上能被刷掉几千块。

### 4.1 必须做的成本控制

1. **限流**：已实现内存限流（6 次/分钟/IP）。多实例部署需换共享存储。
2. **输入裁剪**：payload 只发结构化命盘，不发用户原文长文本（问题限制 500 字，已用 Zod 约束）。
3. **输出上限**：`max_tokens: 2000`（已设），提示词要求 600–900 字。
4. **缓存**：同一 `input + question` 的哈希结果可缓存 24 小时（未实现，建议上线前加，能省掉大部分重复请求）。
5. **预算熔断**：在服务商侧设置月度硬上限；应用侧记录每日调用计数，超阈值直接返回「今日额度已用完」。
6. **不默认开启**：未配置密钥时功能自然关闭，避免误部署产生费用。

### 4.2 供应商选择

- **接口层已抽象**：`AI_PROVIDER` 二选一，`AI_BASE_URL` 可指向任何 OpenAI 兼容网关。换供应商不需要改代码。
- **合规优先**：面向国内用户时，选境内服务可避免个人信息出境问题（见 §2.2）。
- **不要在前端直连模型**：密钥会暴露，且无法限流。

## 6. 回滚与降级

| 故障 | 降级行为 |
| --- | --- |
| 模型服务不可用 | 解读页仍显示规则解读，AI 面板显示错误 + 重试；排盘、起卦、黄历完全不受影响 |
| 未配置密钥 | 同上，且给出配置说明 |
| 历法库异常 | `buildChart` 抛错，页面显示「排盘失败」与可能原因，不返回空盘 |
| localStorage 不可用 | 全站可用，仅不保存历史 |
| 想临时关掉 AI | 删除 `AI_API_KEY` 环境变量并重启，无需改代码、无需重新构建 |
